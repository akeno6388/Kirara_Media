# Kirara_Media

> 一款基于 Kotlin + Jetpack Compose 的 Android 客户端，用于在手机上统一使用与管理 Kirara_Server 上的 Kirara Media 服务。
> 通过 **KIRARA 通行证登录 → 链接令牌 → 打开媒体页** 三步模型，实现一次配置、自动认证登录、评论与互动消息直达。

## ✨ 功能特性

- 🔐 **KIRARA 通行证登录**：账号密码登录 / 冷启动自动续期（RefreshToken 轮换 + 设备绑定 + 串行刷新门防互吊销）
- 🔗 **令牌管理器**：集中管理登录令牌，支持**手动录入**与**二维码导入**（规划中），敏感字段经 **Android Keystore AES-256-GCM** 加密后落盘，AccessToken 仅存内存
- 🖥️ **Media 内嵌浏览**：原生 WebView 承载 Jellyfin Web 界面，`viewport`/`dvh` 与手机浏览器对齐，支持**视频全屏**（沉浸式宿主）与**旋转保活**（旋转不中断播放、不退回首页）
- 🤖 **自动登录引擎**：平移桌面端 MediaScheme 判据状态机（①~⑥ 顺序判定、SPA 就绪等待、网络错误页自愈、**温和移交**不误提交），支持重启免登录、快速已登录检测
- 💬 **议题评论系统**：媒体详情页自动识别资源并显示评论入口，支持评论 / 回复 / **@提及**（用户选择器 + 实时着色 + 整字段删除）/ 点赞（乐观更新），与桌面端**同一资源键**数据互通
- 🗣️ **社区页**：Kirara Media 首页分享列表，卡片式浏览、点赞、资源标题一键跳回源页面；评论可「发送并分享」
- 🔔 **互动通知**：被 @ / 被回复 / 被点赞实时推送（SignalR 长连接）+ 系统通知栏提醒，**退出软件后仍可接收**（WorkManager 周期补拉，**无前台服务、无常驻通知**），未读绿点、已读 / 全部已读 / 全部清除
- 🎨 **外观主题系统**：跟随系统 / 手动明暗 / 48 色 Kirara 风格主题色，状态栏与控件联动即时生效
- 🧹 **数据管理**：一键清空缓存（网页缓存 / 站点 Cookie 与存储 / 图片缓存）或清空全部数据（含账号与令牌），清理后自动关闭软件
- ⬆️ **应用内更新**：检查服务端发布版本，展示更新说明并下载安装新版本 APK
- 🧭 **一体化导航**：媒体 / 社区 / 互动 / 设置 四个常驻标签页，媒体 WebView 切页保活不重载


## 📋 系统要求

- **操作系统**：Android 11（API 30）及以上
- **运行内存**：建议 4GB 及以上
- **存储空间**：安装约 60MB，运行缓存另需约 30MB 以上
- **网络环境**：需可访问 Kirara_Server 服务域名（认证 API 与 Kirara Media 站点，默认端口 `1010`）
- **系统内核**：需设备自带的 Android System WebView（Android 11+ 设备通常已较新）
- **Google 服务**：**无需 GMS**（不依赖 Google Play 服务，通知不依赖 FCM）
- **架构**：arm64-v8a / armeabi-v7a / x86_64

## ⬇️ 安装与更新

1. 前往本仓库 **Releases** 页面下载最新安装包（`Kirara_Media_vX.X.X.apk`）
2. 在手机上允许「安装未知来源应用」后完成安装
3. 首次启动后登录 Kirara_Server 通行证，即可开始使用
4. 软件内置更新检查，可展示版本说明并引导下载安装新版本

> ⚠️ 安装包已使用正式签名；若此前安装过不同签名的旧版本，覆盖安装会失败，需先卸载（会清除本地数据，需重新登录）。


## 🚀 快速开始

### 三步上手

```
① 登录 KIRARA 通行证  →  ② 链接令牌  →  ③ 打开媒体页自动登录
```

1. **登录通行证**：输入 Kirara_Server 账号密码；勾选记住登录后，后续冷启动自动续期进入主界面
2. **链接令牌**：在「设置 → 令牌管理器」手动录入（或扫码导入）媒体账户令牌；媒体页登录界面右下角的 **「链接令牌」圆点**也可直接触发自动登录
3. **一键直达**：进入「媒体」标签页，引擎自动等待页面就绪、填充凭据并提交；成功后即刻进入 Kirara Media 首页

> 💡 媒体页登录失败时不会强行提交空密码，会在圆点上给出**具体失败原因**与重试 / 设置 / 关闭入口（温和移交），页面始终可手动登录。

### 常用操作

- **媒体浏览**：详情页右下角悬浮按钮打开评论区，标题栏自动显示视频名（Jellyfin API 优先、DOM 兜底）
- **评论区**：支持评论 / 回复 / 点赞 / @提及；输入 `@` 调起用户选择器，合法提及自动配色并整体删除
- **社区页**：浏览首页分享，点资源标题 chip 可跳回媒体页对应页面
- **互动页**：查看被 @ / 被回复 / 被点赞通知；支持已读、全部已读、全部清除；有新消息时导航栏显示绿点
- **数据管理**：设置页可清空缓存或清空全部数据（清空后软件自动关闭，重新打开即为全新状态）
- **通知优化设置**：「后台保持设置」跳转系统电池优化白名单，「自动启动」跳转应用信息页

核心设计：

- **分层架构**：Compose UI 层 / ViewModel 层 / 核心引擎（**不含任何 `android.webkit` 依赖**）/ WebView 桥（全 App 唯一触碰 WebKit 处）/ 数据层（Retrofit + Keystore 加密存储）
- **脚本级复用桌面端**：自动登录 JS（预登录 / 自动登录 / 标题探针 / 登录页三态探针）与判据顺序**逐字平移**，桌面实测过的选择器不作"优化"
- **资源键精确匹配**：`{scheme}://{authority}{path(+hash)}` 与桌面端逐字一致，评论/分享跨端同桶互通
- **串行刷新门**：RefreshToken 为轮换吊销语义，401 时以单飞锁统一刷新后重放，避免并发互吊销
- **凭据安全**：Android Keystore 生成不可导出密钥（AES-256-GCM）加密私有文件，AccessToken 仅内存，日志只记「是否有值」
- **通知两段式接收**：进程内存活时 SignalR 实时推送；进程被回收后由 WorkManager 增量补拉兜底（首次只建基线不刷屏），历史同步静默入列表

## ❓ 常见问题

<details>
<summary><b>退到后台一段时间后收不到实时通知？</b></summary>

部分国产系统在应用退到后台后会较快切断其网络访问，导致实时推送通道断开（断开期间的消息将由补拉机制在下次联网时送达）。
可在「设置 → 通知优化设置」中点击「后台保持设置」将本应用加入电池优化白名单，或通过「自动启动」跳转到系统应用信息页开启自启动，以提升后台及时性。
</details>

<details>
<summary><b>通知为什么可能延迟十几分钟？</b></summary>

为保证通知栏**不出现任何常驻通知**，本应用不使用前台服务；在应用进程被系统回收后，改由系统的周期任务补拉新消息，因此最坏延迟约为一个调度周期（约 15 分钟）。应用在前台或后台存活期间，通知均为实时推送。
</details>

<details>
<summary><b>网络异常时还能使用吗？</b></summary>

应用支持一定的降级与自愈：媒体页加载失败会自动重试并给出友好提示；用户目录（@候选）不可用时降级为空列表；评论与通知在恢复网络后可重新加载与补拉。核心的媒体浏览本身依赖网络。
</details>

<details>
<summary><b>令牌/数据存在哪里？</b></summary>

所有数据均保存在应用私有目录中，令牌与凭据字段已加密（Android Keystore，密钥不可导出），其他应用与文件管理器无法访问。卸载应用即全部清除。
如需重置，可在「设置 → 数据管理」中选择「清空所有数据」（会一并清除登录状态与令牌，需重新登录）。
</details>

<details>
<summary><b>安装时提示签名冲突 / 覆盖安装失败？</b></summary>

说明手机上已存在不同签名的旧版本（例如早期测试包）。请先卸载旧版本再安装新包；卸载会清除本地数据，需要重新登录通行证并重新录入令牌。
</details>

<details>
<summary><b>视频全屏或旋转时体验异常？</b></summary>

视频全屏走系统 Fullscreen API，宿主已做沉浸式处理，可滑动唤出系统栏；播放中旋转设备会保留播放状态与页面进度（已声明相应 `configChanges`），不会退回首页。
</details>
